# 12 · Functional requirements — v0.3 "Ledger"

**Scope (concept):** sources by DOI, PMID and PDF, full text, claim links, the verification pass, proposed sources, `tlilli-cite` and `tlilli-verify`, CSL JSON and BibTeX export.
**Release:** tag `v0.3.0`. **Gate:** [G3](40-roadmap-and-gates.md#gate-g3-v030-ledger). **Milestone:** `v0.3 Ledger`.

## 12.1 Sources

**FR-03-001 Add by identifier.** The author MUST be able to add a source by DOI, PMID, PMCID or arXiv ID; metadata is resolved to CSL-JSON through Crossref (DOI), NCBI E-utilities (PMID/PMCID) and the arXiv API, with doi.org content negotiation as fallback; results are cached; failures leave the source `unresolved` with the raw identifier.
- AC: 20 identifiers from the fixture list resolve to correct title/authors/year/container; rate limits respected (Crossref polite pool when an email is set, NCBI 3 req/s); offline adds queue and resolve later.
- Verification: unit with recorded HTTP fixtures (no live network in CI); live smoke at gate. Traces: Source.

**FR-03-002 Add by PDF drop.** Dropping a PDF MUST copy it to `sources/<ulid>/source.pdf`, extract text locally to `source.txt` with page markers, sniff a DOI (regex on the first three pages, then arXiv ID, then title search as a suggestion only), resolve metadata, and show a confirmation card before saving.
- AC: on the OA fixture PDFs, DOI sniffing succeeds on ≥ 90%; extraction within `NFR-PERF-007`; a scanned PDF without text layer yields `unverifiable` full text with a message (no OCR in scope).
- Verification: fixture tests; fuzzing. Traces: Source.

**FR-03-003 Full text retrieval.** For a resolved source without a PDF the app MAY fetch open-access full text on author action: Europe PMC (full-text XML for PMC articles), Unpaywall (OA location → PDF), stored locally; paywalled sources stay `fulltext: none` with a prompt to drop the PDF.
- Verification: recorded-HTTP tests. Traces: Source.

**FR-03-004 Deduplication and status.** Sources are deduplicated by normalized DOI (case-insensitive, prefix-stripped), then by PMID/arXiv, then by fuzzy title+year with a merge prompt; status ∈ {resolved, proposed, unresolved}; a source card shows metadata, identifiers, full-text availability, claim-link count and the runs that touched it.
- Verification: unit; e2e. Traces: Source.

**FR-03-005 Source editing.** The author MUST be able to edit CSL fields, attach or replace a PDF, delete a source (refused while claim links exist unless cascaded with confirmation).

## 12.2 Claim links

**FR-03-010 Claim link model.** A claim link MUST connect a span, a source, a quoted passage (≤ 2 sentences, verbatim from the full text with a locator: page or section), a verification status ∈ {supported, partially_supported, unsupported, contradicted, unverifiable}, a rationale, and the run that last checked it (or `author`).
- Verification: unit; schema. Traces: Claim link.

**FR-03-011 In-text markers.** Citations are stored in span text as `[@key]` markers (keys are stable per source, `author-year-slug`), rendered in the editor as numeric or author-year chips (style sheet in v0.4; default numeric), and the reference count counter (FR-01-023) reflects distinct cited sources.
- AC: markers survive segmentation (never split a sentence); deleting a source with markers converts them to `[@missing:key]` with a warning.
- Verification: unit; property.

**FR-03-012 Author-made links.** The author MUST be able to create a link by selecting a span and a source, optionally pasting the passage; author links start `unverifiable` until a run checks them (or `supported` if the author marks them so).

**FR-03-013 Verification follow-ups.** The agent's required follow-up per status is enforced by the review pane as a checklist, not by the server: `partially_supported` expects a comment and a hedged alternative; `unsupported` a comment and a search for a better source; `contradicted` a high-severity comment and a removal or reversal suggestion; `unverifiable` a comment asking for the PDF. The run report lists links that lack their follow-up.
- Verification: unit on the report builder; gate rubric.

## 12.3 Ledger tools and resources (MCP)

**FR-03-020 `source_resolve(identifier)`.** Metadata lookup and duplicate check; no write; returns CSL-JSON and `exists: source_id|null`.
**FR-03-021 `source_propose(run_id, identifier, reason, passage)`.** Creates a `proposed` source; MUST carry an identifier the server can resolve and a candidate passage; refused otherwise (`FR-03-022` dependency).
**FR-03-022 Proposed sources become real on accept.** A proposed source is promoted to `resolved` only when the author accepts a suggestion carrying a claim link to it; unaccepted proposals are purged on run close (listed in the report).
**FR-03-023 `fulltext_search(source_id|all, query)`.** FTS5 search over extracted text; returns passages (≤ 2 sentences) with locators, labelled untrusted (`INV-07`).
**FR-03-024 `claim_link_set(run_id, span_id, source_id, quote, locator, status, rationale)`.** Create or re-verify a link; the quote MUST be found verbatim (whitespace-normalized) in the stored full text or the call is refused with `quote_not_found`; allowed on spans inside the queue, on spans in the citation-verification standing-check scope (sections touched by the run or whole manuscript on demand), and on any span already linked to the source.
**FR-03-025 Resources.** `tlilli://manuscript/{id}/ledger` (sources and claim links), `tlilli://source/{id}/fulltext` (text with page markers, untrusted envelope), `tlilli://source/{id}/pdf` (binary).
**FR-03-026 Suggestions carry claim links.** `suggest_replace`/`suggest_insert` alternatives accept `claim_links[]` referencing resolved or proposed sources with quotes; accepting the alternative creates the links.
- Verification for 12.3: contract tests with golden transcripts; property test that `claim_link_set` never changes span text; fuzzing. Traces: MCP surface.

## 12.4 Standing check: citation verification

**FR-03-030 Standing check toggle.** Per manuscript the author MUST be able to turn on "verify citations" as a standing check for touched sections every run, or request a whole-manuscript verification as a document-level request; the frozen queue records the scope.
**FR-03-031 Verification results.** Results land as comments (severity by status) attached to the citation chip and the span; any fix is a separate suggestion; the review pane groups verification results under "Checks".
- Verification: e2e with a seeded manuscript (10 citations: 6 supported, 2 partial, 1 unsupported, 1 unverifiable).

## 12.5 Skills and prompts

**FR-03-040 `tlilli-cite`.** Ledger first, then the agent's own literature servers; never propose without an identifier and a passage; prefer sources already in the ledger; explain choice in the rationale.
**FR-03-041 `tlilli-verify`.** The five statuses with definitions and examples, the comment format, the required fix per status, how to quote (≤ 2 sentences, exact), how to handle no full text.
**FR-03-042 Prompt `verify-citations`.** Mirrors `tlilli-verify` for clients without skills.

## 12.6 Citation export

**FR-03-050 CSL-JSON export.** Export the ledger (all or cited) as CSL-JSON; deterministic ordering.
**FR-03-051 BibTeX export.** Export cited sources as `.bib` with stable keys matching `[@key]`; Unicode preserved or escaped per setting.
**FR-03-052 Reference list in Markdown export.** Markdown export renders a References section in the chosen CSL style (default `apa`, `vancouver`, `nature` bundled; any `.csl` file loadable) via hayagriva, with numeric or author-year in-text rendering.
- Verification: snapshot tests against the CSL test-suite subset; `NFR-I18N-002` locales.

## 12.7 UI

**FR-03-060 Ledger pane.** Lists sources with status, full-text icon, link counts, search and filters; drag a source onto a span to cite; source card with the PDF viewer (first page thumbnail, open externally).
**FR-03-061 Citation chips.** Chips show status colour and glyph; hovering shows passage and rationale; clicking opens the link editor.
**FR-03-062 Network panel.** Settings → Network lists the allow-listed hosts, the optional polite-pool email, cache size and a "clear cache" action (`NFR-SEC-004`).

## 12.8 Gate scenario (summary)

On the maintainer's manuscript: add 20 sources (10 by DOI/PMID, 5 by PDF drop, 5 via agent proposal), link them, run verification with Claude Code; author judges ≥ 90% status agreement; exports open in Zotero (CSL-JSON) and compile with BibTeX; `NFR-SEC-004` allow-list holds under a recording proxy.
