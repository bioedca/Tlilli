# 14 · Functional requirements — v0.5 "Beyond the article"

**Scope (concept):** methods from protocols, reviewer response, cover letter, shared source pool, Zotero import, ChatGPT connector through the guarded tunnel plus MCP prompts.
**Release:** tag `v0.5.0`. **Gate:** [G5](40-roadmap-and-gates.md#gate-g5-v050-beyond-the-article). **Milestone:** `v0.5 Beyond the article`.

## 14.1 Methods from protocols

**FR-05-001 Materials pane.** A manuscript MAY hold protocol documents (Markdown, docx, PDF) imported into a Materials pane, stored under `sources/protocols/<ulid>/`, text-extracted and searchable; protocols are untrusted input like sources (`INV-07`).
**FR-05-002 Protocol stubs.** An idea stub with cite hint `protocol: <name>` is drafted from the protocol text; the accepted paragraph carries a provenance link to the protocol passage (`claim_links` with `source_kind: protocol`).
**FR-05-003 Methods checks.** `sweep_check` adds: every method named in Results has a Methods paragraph; reagent and instrument names consistent across Methods, Results and Legends.
- Verification: fixture protocol + manuscript; contract tests.

## 14.2 Reviewer response

**FR-05-010 Document type.** A `reviewer_response` manuscript is created from a parent article manuscript; reviewer text imports (paste, docx, PDF) as comment blocks split per reviewer and point; each point gets a response block.
**FR-05-011 Cross-links.** A response block links to the article spans changed in reply (selected by the author or proposed by the agent via `suggest_link`); the agent checks that every promised change exists in the article (`response_check(run_id, manuscript_id)` returns promises without a linked change).
**FR-05-012 Skill `tlilli-response` and prompt `reviewer-response`.** Tone (courteous, specific, point-by-point), structure (quote, response, change made with location), cross-linking, never arguing beyond the data.
**FR-05-013 Export.** Reviewer response exports to docx (point-by-point table or paragraphs) and Markdown; reviewer text is marked as quoted.
- Verification: fixture reviews; e2e; gate.

## 14.3 Cover letter

**FR-05-020 Document type.** A `cover_letter` manuscript with the journal's style sheet (presets include editor salutation conventions and length), drafted as a suggestion from the article's abstract and a significance stub; exports to docx and PDF.

## 14.4 Shared source pool

**FR-05-030 Workspace pool.** A workspace MAY hold a shared source pool; each manuscript's ledger references pool sources by id; adding a source offers "to pool" or "manuscript only"; moving sources between pool and manuscript keeps claim links.
**FR-05-031 Pool resource.** `tlilli://workspace/pool` lists pool sources; `fulltext_search(all)` spans pool and manuscript sources with the scope indicated.

## 14.5 Zotero import

**FR-05-040 Better BibTeX export import.** Import `.bib`/CSL-JSON exported by Zotero (Better BibTeX) with attachments path mapping to copy PDFs.
**FR-05-041 Local API.** Optional read-only import from the Zotero desktop local API (`http://localhost:23119`), collections browsable, items imported as sources with PDFs; the host is added to the allow-list only while the feature is enabled (`NFR-SEC-004`).
- Verification: recorded responses; manual at gate.

## 14.6 ChatGPT connector

**FR-05-050 Guarded tunnel.** Settings → Agents → ChatGPT MUST offer a one-command tunnel using the user's installed `cloudflared` or `ngrok` (detected on PATH; never bundled, ADR-0005), exposing the HTTP transport under the workspace token, showing the public URL, status, request log and a Stop button; the tunnel stops with the app (`NFR-SEC-006`).
**FR-05-051 Prompts carry the workflow.** All skills exist as MCP prompts (`run`, `revise-section`, `verify-citations`, `consistency-sweep`, `draft-from-stubs`, `reviewer-response`) so a client without skills gets the workflow.
**FR-05-052 Plan caveat in product.** The connector setup page MUST state the current ChatGPT plan matrix for write-capable connectors (re-checked at v0.5 start, D-038) and label the connector read-mostly where applicable.
- Verification: e2e with a local HTTPS stand-in for the tunnel; manual with ChatGPT at gate.

## 14.7 Gate scenario (summary)

Import two reviewer reports for the maintainer's manuscript, draft responses with Codex, cross-link changes, `response_check` finds a planted unfulfilled promise; a cover letter drafted; shared pool used by two manuscripts; Zotero import of a 50-item collection; ChatGPT (Developer mode) connected through the tunnel runs `verify-citations`.
