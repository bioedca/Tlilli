# 10 · Functional requirements — v0.1 "Black ink"

**Scope (concept):** Tauri app, document model with stable IDs, sections, blocks, spans, comments with tags, idea stubs, snapshots, Markdown and basic docx import. No agent yet.
**Release:** tag `v0.1.0`. **Gate:** [G1](40-roadmap-and-gates.md#gate-g1-v010-black-ink). **Milestone:** `v0.1 Black ink`.

Each requirement lists: statement · acceptance criteria (AC) · verification · traces (concept object, later MCP surface).

## 10.1 Workspace and manuscripts

**FR-01-001 Create and open a workspace.** The app MUST create a workspace folder `<name>.tlilli/` containing `workspace.sqlite`, `sources/`, `figures/`, `exports/`, `logs/`, `backups/` and a `tlilli.json` marker with schema version, and MUST open an existing workspace by folder.
- AC: creating writes all entries; opening a folder without `tlilli.json` is refused with a clear message; opening a newer schema is refused (`NFR-COMPAT-001`); the last five workspaces are listed on launch.
- Verification: e2e smoke; unit tests on layout. Traces: Workspace.

**FR-01-002 Many manuscripts per workspace.** A workspace MUST hold any number of manuscripts, each with a type (`article` in v0.1; `reviewer_response` and `cover_letter` reserved), title, created/updated timestamps, and MUST list them in a sidebar with search.
- AC: create, rename, duplicate, archive (soft delete) and permanently delete (confirmed) a manuscript; archived manuscripts hidden by default.
- Verification: unit; e2e. Traces: Manuscript.

**FR-01-003 Sections with roles.** A manuscript MUST contain ordered sections, each with a role from {Abstract, Introduction, Results, Discussion, Methods, Legends, References, Custom(name)}, reorderable by drag and keyboard.
- AC: new article manuscripts get the IMRaD template; a section may be renamed, reordered, merged into a neighbour or deleted (confirmed when non-empty); role is shown in the outline and exported as metadata.
- Verification: unit; e2e. Traces: Section.

## 10.2 Blocks, spans and identity

**FR-01-010 Block kinds.** Sections MUST contain ordered blocks of kind paragraph, heading (levels 1–3), idea stub, figure, table, caption, equation, with a ULID assigned at creation that never changes (`INV-10`).
- AC: splitting a paragraph keeps the ULID on the first half and mints one for the second; merging keeps the first; moving keeps the ULID; a block's ULID is visible in an inspector.
- Verification: property tests over random edit sequences. Traces: Block.

**FR-01-011 Sentence spans.** Every paragraph MUST be segmented into sentence spans with stable IDs. Segmentation is rule-based (terminal punctuation, closing quotes/brackets, abbreviation list, decimal numbers, initials, common Latin abbreviations, citation markers) and seeded by the manuscript's abbreviation list (empty in v0.1; style sheet in v0.4 feeds it).
- AC: on the English fixture corpus, segmentation agrees with the hand-labelled boundaries on ≥ 98% of sentences; "e.g.", "Fig. 3", "et al.", "p < 0.05." and "(Smith et al., 2019)." do not split; a per-paragraph manual split/join override exists and persists.
- Verification: fixture tests; property test (concatenation of spans equals paragraph text). Traces: Span.

**FR-01-012 Span-ID stability by diff anchoring.** After any author edit, span IDs MUST be reassigned by diffing old and new segmentation: unchanged and lightly edited sentences (similarity ≥ 0.6 by normalized token overlap, position-aware) keep their ID; new sentences mint new IDs; deleted sentences retire their ID with a tombstone pointing to the nearest surviving span. "Nearest" is in document order, looking back first; with no surviving span in the manuscript the tombstone points at the block that held it, else at its section, else it is an orphan whose anchors are listed for manual re-anchoring (R-01). A locked span (`FR-01-021`, `FR-04-003`) MUST keep its ID through any author edit confined to it, whatever the similarity: splitting it keeps the ID on the first part, a merge keeps the locked span's ID (the first, if both are locked), and deleting it tombstones it (D-073).
- AC: on the revision corpus (scripted edit series over synthetic manuscripts plus the maintainer's real revision histories), ≥ 99% of sentences the author did not touch keep their ID and 100% of locked spans not deleted keep theirs ([01](01-vision-and-scope.md) §6); a sentence rewritten in place keeps its ID when similarity ≥ 0.6; anchors (comments, requests, later claim links and provenance) follow the ID; tombstones resolve to a neighbour for display.
- Verification: property tests; corpus metric reported at gate. Traces: Span, Request, Comment.

**FR-01-013 Idea stubs.** An idea stub MUST be a dashed block with fields: notes (required), cite hint (free text, DOI, or "find one"), tone (hedged, assertive, general reader), target length (one sentence, two, about N words), level (sentence or paragraph), and for paragraph level an argument order list.
- AC: a stub renders distinctly, is never counted in word counts, exports as a visible placeholder in Markdown (`> [stub] …`) and as a comment in docx; stays in place until replaced (v0.2 accept).
- Verification: unit; snapshot export. Traces: Idea stub.

**FR-01-014 Figures, tables, equations (placeholder level).** Figure blocks MUST hold one or more image files (PNG, JPEG, SVG, PDF) copied into `figures/<ulid>/`, panel labels, a caption block and the computed list of in-text references ("Fig. 2", "Figure 2b"). Table blocks MUST hold cells (CSV or pasted grid) and a caption. Equation blocks hold LaTeX source and render with KaTeX.
- AC: drop an image to create a figure; caption editable as a paragraph; in-text references detected by regex and listed; tables editable cell-wise.
- Verification: unit; e2e. Traces: Figure asset, Block.

## 10.3 Editing

**FR-01-020 Structured editor.** The editor MUST be ProseMirror with a schema mirroring sections, blocks and spans; every transaction MUST map to one or more core events and the view MUST re-render from the core's response (`INV-02`).
- AC: an injected fault that drops the core response leaves the view unchanged (no optimistic divergence); undo/redo is event-based and crosses sessions (undo after restart).
- Verification: UI integration tests with a mocked core; property test replay. Traces: Architecture.

**FR-01-021 Comments with tags (requests).** The author MUST be able to select a span, block or section and attach a comment with an optional tag from the action vocabulary (sentence: paraphrase, tighten, expand, formalize, split, merge, cite, hedge, strengthen; paragraph: fix flow, strengthen topic sentence, reorder sentences, cut to N words, expand stub; section: restructure, check logic chain, check journal conventions, draft from outline; document: consistency sweep, citation verification) and a free-text note. Tagged and untagged comments are Requests queued for the next run.
- AC: Cmd/Ctrl-K opens a fuzzy tag palette; Enter commits; the queue badge shows the count; requests are listed in a Queue pane grouped by section; a request can be edited or withdrawn until sent; "do not touch" marks a span locked.
- Verification: e2e keyboard suite; unit. Traces: Request, Comment, Locked spans.

**FR-01-022 Send (v0.1 behaviour).** Send MUST freeze the queue into a Run record with status `open`, take a snapshot, and make the manuscript read-only with a status chip "waiting for agent" and a Cancel action. With no agent connected (v0.1) the run can only be cancelled, which restores editing and keeps the requests queued.
- AC: the state machine idle → open → cancelled is exercised; requests survive cancel; the chip is announced to screen readers.
- Verification: state-machine tests; e2e. Traces: Run, Turn protocol.

**FR-01-023 Live counters.** The editor MUST show word counts per section and total, sentence count, and reference count (0 until v0.3), updated within 100 ms of typing.
- Verification: unit; e2e. Traces: Style sheet limits (v0.4 adds limits).

## 10.4 Snapshots, history and diff

**FR-01-030 Append-only event log.** Every change MUST be an event with actor, timestamp, parent hash and payload, persisted before the UI confirms it (`NFR-REL-001`).
- AC: replay of the log from genesis reproduces the current state byte-for-byte; the hash chain detects a tampered or truncated log; permanent deletion of a manuscript (`FR-01-002`), the only removal, deletes its whole chain and its `chain_heads` row in one transaction with a workspace-chain event that records the final head, so verification reports a deletion, not truncation (D-073).
- Verification: property tests; corrupted fixtures. Traces: Event log.

**FR-01-031 Snapshots.** The app MUST take snapshots automatically (on Send, on import, every 50 events or 10 minutes while editing) and on demand with a label; snapshots are immutable and listed in History.
- AC: restore-to-snapshot creates a new event (never rewrites history) and preserves IDs; snapshot storage is deduplicated (content-addressed blocks).
- Verification: unit; e2e. Traces: Snapshot.

**FR-01-032 Diff view.** History MUST show a sentence-level diff between any two snapshots or between a snapshot and now, with insertions, deletions and moved blocks distinguished, navigable by keyboard.
- AC: the diff of the reference manuscript renders in ≤ 1 s (`NFR-PERF-004`); diffs are exportable as Markdown.
- Verification: snapshot tests; bench. Traces: Snapshot.

**FR-01-033 Show ink (foundation).** A "show ink" toggle MUST exist and tint spans by provenance; in v0.1 everything is author ink, and the mark is recorded per span from the first event so v0.2 history is complete (`INV-06`).
- Verification: unit. Traces: Provenance mark.

## 10.5 Import and export

**FR-01-040 Markdown import.** Import a `.md` file: headings become sections (level 1) and heading blocks (2–3), paragraphs become paragraph blocks, blockquotes starting with `[stub]` become idea stubs, images become figures, tables become table blocks, `$$` blocks equations; unsupported constructs become raw blocks listed in an import report (`NFR-REL-006`).
- Verification: snapshot tests on fixtures. Traces: Import.

**FR-01-041 Basic docx import.** Import paragraphs, headings (by style name or outline level), images, tables and footnotes-as-comments from `.docx`; Word comments become author comments anchored to the matching span; tracked changes are accepted on import with a warning.
- AC: the fixture set (Word 365, LibreOffice, Google Docs exports) imports without crash; text equality with the docx text content ≥ 99.9%.
- Verification: snapshot tests; fuzzing nightly. Traces: Import.

**FR-01-042 Markdown export.** Export a section or manuscript to Markdown, optionally with span-ID markers (`<!-- sp:01H… -->`) for the agent view; without markers the output is clean CommonMark.
- Verification: snapshot tests; round-trip test import→export→import. Traces: Export.

**FR-01-043 Canonical JSON export.** `tlilli export --canonical <workspace> <out-dir>` (CLI) and the UI equivalent MUST write deterministic JSON files per manuscript (stable key order, LF, trailing newline) suitable for git diffing, carrying `$schema` and version (`NFR-COMPAT-002`), and `tlilli import --canonical` MUST reconstruct an equivalent workspace (`NFR-REL-008`).
- Verification: property round-trip; schema validation. Traces: Storage.

## 10.6 CLI (v0.1 subset)

**FR-01-050 `tlilli` command.** The CLI MUST provide `export --canonical`, `import --canonical`, `import <file.md|docx>`, `doctor` (prints versions, schema version, log location, checks the workspace), and `--version`. Exit codes: 0 success, 1 user error, 2 internal error (INTERSECT CI/CD: rely on exit codes).
- Verification: CLI integration tests with `assert_cmd`. Traces: Architecture.

## 10.7 Shell, settings, diagnostics

**FR-01-060 App shell.** Native window with menu (File, Edit, View, Manuscript, Help), recent workspaces, OS theme following, window geometry persistence, single-instance behaviour (opening a second workspace opens a new window).
- Verification: e2e smoke per OS at gate.

**FR-01-061 Settings.** Settings MUST include: default workspace location, theme, segmentation overrides, log level, diagnostics copy (`NFR-OBS-004`), and (v0.2) the agent connection panel.
- Verification: e2e.

**FR-01-062 Crash handling.** Panics MUST be caught at the Tauri command boundary, logged, written to `crashes/` and surfaced as a dialog offering to copy diagnostics (`NFR-OBS-003`).
- Verification: panic-injection test.

## 10.8 Out of scope for v0.1 (deferred by design)

Agent connection, suggestions, review pane (v0.2); sources and citations (v0.3); style sheet, sweep, docx export, LaTeX, PDF (v0.4); other document types (v0.5); installers and docs site polish (v1.0). Builds in v0.1 are CI artifacts and a draft GitHub Release used for the gate test.
