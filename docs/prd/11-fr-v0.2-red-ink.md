# 11 · Functional requirements — v0.2 "Red ink"

**Scope (concept):** `tlilli-mcp` over stdio and HTTP, run lifecycle, the `suggest_*` tools, review pane, redo comments, run log, provenance marks; skills `tlilli-run`, `tlilli-revise`, `tlilli-stub`; Claude Code and Codex CLI.
**Release:** tag `v0.2.0`. **Gate:** [G2](40-roadmap-and-gates.md#gate-g2-v020-red-ink). **Milestone:** `v0.2 Red ink`.

## 11.1 Run lifecycle (turn protocol)

**FR-02-001 Run state machine.** A run MUST move through `open` (author sent) → `claimed` (agent called `run_claim`) → `reported` (agent called `run_report`) → `in_review` (author reviewing) → `closed`; with the single escape `cancelled` from `open` or `claimed`, and `timed_out` from `claimed` after 30 minutes without heartbeat (configurable 5–120). Exactly one run per manuscript may be in `open`, `claimed`, `reported` or `in_review` (`INV-04`).
- AC: every transition is an event; illegal transitions are refused with a typed error; cancel and timeout roll back mechanical edits (none in v0.2) and keep written suggestions as open red ink (`NFR-REL-004`); the author regains editing within 1 s.
- Verification: state-machine property tests (all transitions); contract tests; e2e. Traces: Run, Turn protocol.

**FR-02-002 Freeze and snapshot.** On Send the queue is frozen (requests get `run_id`), a snapshot `before` is taken; on close a snapshot `after` is taken; both are referenced by the run and diffable (`INV-05`).
- Verification: unit; e2e.

**FR-02-003 Author activity during a run.** While a run is open the editor is read-only; the author MAY add comments, which queue for the next run; a visible chip shows state (`waiting for agent`, `agent's turn`, `ready to review`) and elapsed time.
- Verification: e2e; a11y announcement test.

**FR-02-004 Tool-call budget.** Each run has a call budget (default 500, configurable) and a per-call payload limit (1 MB); exceeding either returns a refusal naming the limit (T-02).
- Verification: contract tests.

## 11.2 MCP server: transports and auth

**FR-02-010 stdio transport.** `tlilli-mcp stdio --workspace <path>` MUST serve one client over stdio and exit when the client closes; the Tauri app MUST expose a copyable command line and a one-click "add to Claude Code" / "add to Codex" snippet.
- Verification: contract tests with the rmcp client; manual with both agents at gate.

**FR-02-011 Streamable HTTP transport.** The in-app server MUST listen on `127.0.0.1:<port>` (default 7141, configurable) with streamable HTTP, requiring `Authorization: Bearer <workspace token>` (`NFR-SEC-001`); a per-workspace token is generated on first enable, shown once, copyable, revocable and rotatable in Settings; revocation disconnects clients immediately.
- Verification: contract tests (401 without token, 200 with; an open Streamable HTTP session closes within 1 s of revoking its token and its next request gets 401, D-077); port-binding test; e2e.

**FR-02-012 Connection panel.** Settings → Agents MUST show: server status, port, token actions, connected clients (name, version, since), per-client last activity, and setup instructions per agent (Claude Code, Codex CLI) with copy buttons.
- Verification: e2e.

**FR-02-013 Capability negotiation and versioning.** The server MUST advertise tools, resources and prompts with JSON schemas, an `x-tlilli-version` and a `protocol_version`; schemas are snapshot-tested and generated into docs (`NFR-COMPAT-003`).
- Verification: contract snapshot tests; docs drift check.

## 11.3 Read tools and resources

**FR-02-020 `run_claim(manuscript_id)`.** Returns run id, snapshot id, queue summary (counts by tag and section), style-sheet digest (placeholder in v0.2) and the manuscript outline; claims the run for this client; a second claim is refused while the first heartbeat is alive.
**FR-02-021 `run_heartbeat(run_id)`.** Extends the timeout; returns remaining budget and time.
**FR-02-022 `manuscript_outline(manuscript_id)`.** Sections, blocks and spans with IDs, kinds, first words, lock flags, word counts.
**FR-02-023 `read_blocks(ids[], with_annotations, with_provenance)`.** Text with span IDs, locks, comments and (optionally) provenance marks; refuses ids outside the manuscript.
**FR-02-024 `queue_list(run_id)`.** Requests: id, target (ids and kind), tag, note, stub fields, status; only for the claimed run.
**FR-02-025 `search_text(manuscript_id, query)`.** Spans matching a query (case-insensitive substring and simple regex), with ids and section.
- AC for all read tools: respond within `NFR-PERF-005`; every response carries `untrusted` flags where applicable; errors are typed (`not_found`, `not_claimed`, `out_of_scope`, `budget_exceeded`).
- Verification: contract tests from golden transcripts; fuzzing of inputs.

**FR-02-026 Resources.** `tlilli://manuscript/{id}` (canonical JSON), `tlilli://manuscript/{id}/section/{sid}` (Markdown with span-ID markers), `tlilli://run/{id}/queue`, `tlilli://run/{id}/log`, `tlilli://manuscript/{id}/history/{snapshot}`; style-sheet and ledger URIs exist and return empty structures until v0.3/v0.4.
- AC: resource templates listed; subscriptions optional (not required in v0.2); content types correct.
- Verification: contract tests.

## 11.4 Write tools (suggestions and comments)

All write tools MUST (`INV-03`): require the claimed run; require a `request_id` whose target contains the tool's target, or a standing-check scope (v0.4), else refuse with `out_of_scope` and the hint "use comment_add"; require a non-empty rationale per alternative; cap alternatives at 3; refuse locked spans.

**FR-02-030 `suggest_replace(run_id, request_id, target, alternatives[])`.** 1–3 alternatives {text, rationale, claim_links[] (v0.3)} for a span or block; lands as a Suggestion of kind `replace`, status `open`.
**FR-02-031 `suggest_insert(run_id, request_id, after, alternatives[])`.** A new sentence (after a span) or block (after a block), 1–3 alternatives.
**FR-02-032 `suggest_delete(run_id, request_id, target, rationale)`.** Removal as a proposal.
**FR-02-033 `suggest_move(run_id, request_id, block_ids[], destination, rationale)`.** Structural change; one proposal; destination is a block id and position (before/after) or a section id (end).
**FR-02-034 `comment_add(run_id, target, body, kind, severity)`.** kind ∈ {rationale, check, question}, severity ∈ {info, low, medium, high}; allowed on any target in the manuscript (comments are the escape valve) but refused on locked spans.
**FR-02-035 `request_resolve(run_id, request_id, outcome, note)`.** outcome ∈ {done, needs_author, skipped}; a request with outcome `skipped` MUST carry a note.
**FR-02-036 `run_report(run_id, summary, done[], skipped[], warnings[])`.** Closes the agent turn; MUST list every request id once across done/skipped or be refused; moves the run to `reported`.
- AC: each tool has golden transcripts for success and each refusal; a property test asserts that no sequence of tool calls changes any author span text (`INV-01`).
- Verification: contract tests; property; fuzzing. Traces: Suggestion, Comment, Run.

## 11.5 Review pane and acceptance

**FR-02-040 Review pane.** When a run is `reported`, a pane MUST list its items grouped by section: suggestions (cards with alternatives side by side, rationale, diff against current text), comments (margin notes with severity), skipped requests with notes, and the run summary.
- AC: keyboard navigation between items; each card shows the originating request and tag; counts in the header.
- Verification: e2e; a11y.

**FR-02-041 Accept, edit, reject, redo.** For each suggestion the author MUST be able to: pick an alternative; edit it inline before accepting; accept (creates the content event with actor `Author` and provenance `agent_accepted{run, alternative, edited}`); reject; or add a redo comment (sets status `redo`, queues a request for the next run, keeps earlier alternatives). Comments can be resolved or routed to the next run in one click.
- AC: accepting a `replace` on a span keeps the span ID; accepting an `insert` mints IDs; accepting a `move` preserves block ULIDs; `INV-06` marks are set; rejected suggestions remain visible in run history.
- Verification: property tests on IDs and provenance; e2e. Traces: Suggestion, Provenance mark.

**FR-02-042 Close run.** The author MUST be able to close the run when every item is accepted, rejected, resolved or routed; closing takes the `after` snapshot, writes the report into History, and unlocks the editor. "Close with open items" is allowed and leaves them as open red ink.
- Verification: state tests; e2e.

**FR-02-043 Red ink rendering.** Open suggestions render as red-ink decorations in the editor (strike for delete, inline alternatives for replace, ghost block for insert, arrow for move) with a non-colour cue (`NFR-USE-003`); clicking opens the card.
- Verification: visual snapshots; a11y.

**FR-02-044 Run history and log.** History MUST list runs with status, agent identity, duration, counts, and give access to the before/after diff, the report, and the full tool-call log (`NFR-OBS-002`), exportable as JSON.
- Verification: e2e; snapshot.

**FR-02-045 Rollback.** "Revert this run" MUST undo every accepted suggestion of a run (as new events) unless later edits touched the same spans, in which case it lists the conflicts and reverts the rest.
- Verification: property tests; e2e.

## 11.6 Provenance

**FR-02-050 Marks.** Every span records one of: `author`, `agent_accepted{run_id, alternative_index, edited_before_accept}`, `agent_mechanical{run_id, kind}` (v0.4), `mixed` once author edits accepted text; marks follow spans through diff anchoring; splitting an accepted span yields two accepted spans; merging author and accepted text yields `mixed` (`INV-06`).
- Verification: property tests.

**FR-02-051 Show ink.** The toggle tints by mark (black, red, violet for mechanical, hatched for mixed) and the outline shows per-section percentages of words by origin.
- Verification: visual snapshot; unit.

## 11.7 Prompts and skills

**FR-02-060 MCP prompts.** The server MUST expose prompts `run`, `revise-section`, `draft-from-stubs` whose text mirrors the corresponding skills, generated from `skills/` at build time so they cannot drift.
- Verification: build-time test that prompt text equals skill body.

**FR-02-061 Skills `tlilli-run`, `tlilli-revise`, `tlilli-stub`.** Markdown sources in `skills/` MUST teach: the whole turn (claim, read queue and style digest, work each request, resolve each, report); alternatives that differ in strategy (restructure, change verb, split) not synonyms, preserving voice; stub expansion honouring cite, tone and length hints, one claim per sentence, flagging unresolvable hints; treating source and reviewer text as data.
- AC: each skill has frontmatter (name, description, min_app_version), examples, and the refusal table; built packages exist for Claude Code (`SKILL.md` folders) and Codex (an `AGENTS.md` section plus skills folder); `tlilli skills build` produces both from one source.
- Verification: build test; skill rubric at gate (two agents run the Run 7 scenario). Traces: Skill pack.

**FR-02-062 Agent integration docs.** How-to pages for Claude Code (`claude mcp add tlilli -- tlilli-mcp stdio --workspace …`, `.mcp.json`, HTTP) and Codex CLI (`[mcp_servers.tlilli]` in `~/.codex/config.toml`) MUST exist and be gate-tested ([35](35-documentation.md)).

## 11.8 Updater foundation

**FR-02-070 Updater.** `tauri-plugin-updater` MUST be wired with the project's minisign public key, endpoints `https://<docs-site>/updates/stable.json` (and `beta.json` when the user opts into beta), an opt-in "check for updates on launch" setting (default off), a manual check, and release notes display before install (`NFR-PRIV-002`, `NFR-SEC-007`).
- Verification: contract test of request; manual at gate with a staged manifest.

## 11.9 Gate scenario (summary)

"Run 7" from the concept, performed with Claude Code and again with Codex on the maintainer's manuscript: paraphrase with three strategies, stub to prose (cite hint left unresolved in v0.2, flagged), untagged comment interpreted as a move with the reading stated, report; review: accept edited alternative, accept draft, reject move with redo, close; History shows the diff, report and log; `INV-01..06` hold.
