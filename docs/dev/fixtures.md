# Fixtures

Test fixtures live under `tests/fixtures/`. Most are synthetic and generated from a seed; a few are open-access papers, and the rest are recorded by the test suites themselves. The policy is `PR-TST-016` in [34 Testing](../prd/34-testing.md) and D-027.

The file-by-file record of where each fixture comes from and under which license it is committed is [`tests/fixtures/LICENSES.md`](https://github.com/bioedca/Tlilli/blob/main/tests/fixtures/LICENSES.md). That file is a gated path, and it is the source of truth; this page explains how to work with it.

## What may be committed

- Synthetic text generated by `scripts/gen_fixtures.py` from a seed.
- A small set of open-access papers under CC-BY or CC0, vendored under `tests/fixtures/papers/`, each with a row in `LICENSES.md`.
- Files that the test suites or the project's own dev scripts record: MCP contract transcripts, redacted resolver responses, storage databases.

Nothing else from a third party, and never unpublished data. The maintainer's own revision histories are used locally and at gates and are never committed ([34](../prd/34-testing.md) §4).

## Generating synthetic fixtures

```bash
python3 scripts/gen_fixtures.py --list          # the catalogue of fixture kinds
python3 scripts/gen_fixtures.py --dry-run       # each file with its size and SHA-256; writes nothing
python3 scripts/gen_fixtures.py manuscripts     # write one kind into tests/fixtures/
```

The output depends on the seed and the script alone: one seed gives byte-identical files on every platform and Python version. Generated fixtures use the default seed, 1; changing the seed changes every generated file.

## Fixture kinds

| Kind | Directory | Origin |
| --- | --- | --- |
| `manuscripts` | `tests/fixtures/manuscripts/` | generated |
| `revisions` | `tests/fixtures/revisions/` | generated (generator pending, v0.1) |
| `papers` | `tests/fixtures/papers/` | vendored by hand |
| `transcripts` | `tests/fixtures/transcripts/` | recorded by the MCP contract tests |
| `http` | `tests/fixtures/http/` | recorded and redacted by a dev script (`PR-TST-006`) |
| `db` | `tests/fixtures/db/` | one database per released schema version (ADR-0004) |

No fixture is committed yet: each directory arrives with the first test that uses it. `--list` prints the same catalogue with licenses and descriptions.

## Adding a paper

Follow the steps under "Adding a paper" in `LICENSES.md`. In short:

1. Confirm the license on the publisher's page; only CC-BY (any version) and CC0 are accepted.
2. Add the files under `papers/<first-author>-<year>-<short-title>/`.
3. Add the paper's row to `LICENSES.md`, and an `[[annotations]]` table to `REUSE.toml`.
4. Run `scripts/ci.sh reuse`.

Both files are gated paths, so a pull request that adds a paper needs the maintainer's approval.
